# মঞ্জিল ইন্টারন্যাশনাল ইনস্টিটিউট - ভর্তি প্রক্রিয়া ও ডাটাবেস ডকুমেন্টেশন

এই ডকুমেন্টটি আপনার মাদরাসার বর্তমান স্টুডেন্ট অ্যাডমিশন সিস্টেমের কার্যপদ্ধতি এবং Appwrite ডাটাবেসের সাথে এর সংযোগ বিস্তারিতভাবে ব্যাখ্যা করছে। 

## ১. ভর্তির মূল প্রবাহ (Step-by-Step Process)

ভর্তি প্রক্রিয়াটি ৫টি ধাপে সম্পন্ন হয়:

### ধাপ ১: ব্যক্তিগত তথ্য (Step1PersonalInfo)
- এখানে ছাত্রের নাম (বাংলা ও ইংরেজি), বাবা-মায়ের নাম, **পেশা ও কর্মস্থল** এবং জন্ম তথ্য নেওয়া হয়।
- **ডাটাবেস কানেকশন:** এই তথ্যগুলো Appwrite-এর `students` কালেকশনে জমা হয়।

### ধাপ ২: ঠিকানা (Step2ContactAddress)
- বর্তমান ও স্থায়ী ঠিকানা নেওয়া হয়।
- **ডাটাবেস কানেকশন:** এটিও `students` কালেকশনে যায়। 

### ধাপ ৩: ডকুমেন্ট আপলোড (Step3Documents)
- ছাত্রের ছবি, জন্ম নিবন্ধন/এনআইডি এবং বাবা-মায়ের এনআইডি আপলোড করা হয়।
- **প্রসেস:** ছবিগুলো Cloudflare R2-তে আপলোড হয় এবং সেগুলোর লিঙ্ক `students` কালেকশনের `photoUrl`, `birthCertUrl` ইত্যাদিতে সেভ হয়।

### ধাপ ৪: ভর্তির বিবরণ (Step4EnrollmentInfo)
- এখানে বিভাগ, ক্লাস, সেশন এবং বোর্ডিং টাইপ (আবাসিক/অনাবাসিক) সিলেক্ট করা হয়।
- **নতুন সংযোজন:** এখানে আপনি এখন **"ভর্তি পরীক্ষার ফলাফল"** এবং **"পূর্ববর্তী প্রতিষ্ঠানের বিবরণ"** দিতে পারবেন।
- **ডাটাবেস কানেকশন:** 
  - সেশন ও ক্লাস মাস্টার ডেটাগুলো `sessions`, `classes` এবং `departments` থেকে আসে।
  - মূল এন্ট্রিটি `student_enrollments` কালেকশনে একটি নতুন রেকর্ড তৈরি করে।

### ধাপ ৫: ফিস কালেকশন ও পেমেন্ট (Step5FeeCollection)
- ভর্তির সময় মোট কত টাকা বিল হলো এবং কত টাকা জমা দেওয়া হলো তার হিসাব থাকে।
- **ডাটাবেস কানেকশন:** 
  - মোট বিলটি `fee_invoices` কালেকশনে জমা হয়। 
  - তাৎক্ষণিক পেমেন্টটি `fee_payments` কালেকশনে জমা হয়।

## ২. ফিস ও পেমেন্ট ম্যানেজমেন্ট কীভাবে কাজ করে?

আপনার ডাটাবেসে ফিস দুইভাবে ম্যানেজ হয়:

### ক. ইনভয়েসিং (Bill Generation)
যখন একটি শিশু ভর্তি হয়, সফটওয়্যার `fee_types` থেকে চেক করে ওই ক্লাসের জন্য কী কী ফিস (যেমন: ভর্তি ফি, লাইব্রেরি ফি) প্রযোজ্য। সেই অনুযায়ী একটি **Invoice** রেকর্ড তৈরি হয়।
- **টেবিল:** `fee_invoices`
- **কী পাওয়া যাবে:** মোট টাকা (`totalAmount`), ডিসকাউন্ট (`discount`), এবং বকেয়া (`dueAmount`)।

### খ. পেমেন্ট রেকর্ড (Transaction)
ছাত্রটি ভর্তির সময় যে টাকা জমা দেয়, তার একটি এন্ট্রি হয় এখানে।
- **টেবিল:** `fee_payments`
- **কী পাওয়া যাবে:** কত টাকা জমা দিল (`amountPaid`), পেমেন্ট মেথড (ক্যাশ/বিকাশ) এবং কার মাধ্যমে টাকা জমা হলো (`collectedBy`)।

## ৩. Appwrite-এ করণীয় (Action Items for fixing Database)

ভাই, আপনার Appwrite কনসোলে বর্তমান `students` টেবিলে কিছু অ্যাট্রিবিউট (Attribute) কম আছে যা আমাদের নতুন কোডের সাথে মিলছে না। **অ্যাডমিশন সাকসেসফুল করার জন্য আপনাকে নিচের অ্যাট্রিবিউটগুলো ম্যানুয়ালি Appwrite-এ যোগ করতে হবে:**

### `students` কালেকশনে নিচের কলামগুলো যোগ করুন:
| কলামের নাম (Attribute ID) | টাইপ (Type) | সাইজ (Size) |
| :--- | :--- | :--- |
| `identificationNo` | string | 50 |
| `fatherOccupation` | string | 255 |
| `fatherWorkplace` | string | 255 |
| `motherOccupation` | string | 255 |
| `motherWorkplace` | string | 255 |
| `previousSchoolAddress` | string | 500 |
| `admissionTestMarks` | string | 20 |
| `admissionTestResult` | string | 20 |
| `admissionTestRemarks` | string | 500 |
| `examinerName` | string | 255 |
| `hallId` | string | 50 |
| `hallName` | string | 100 |

### `fee_invoices` কালেকশনে চেক করুন:
- `feeItems` নামে একটি **string** কলাম থাকা জরুরি (যেখানে ফিসের লিস্ট হিসেবে JSON সেভ হবে)।

## ৪. সিস্টেমটি কি এখন সঠিক পথে আছে?
**হ্যাঁ ভাই!** আপনার ডাটাবেস আর্কিটেকচারটি প্রফেশনাল এবং এটি ভবিষ্যতে 'অ্যাকাউন্টিং রিপোর্ট' এবং 'স্টুডেন্ট লেজার' তৈরির জন্য একদম পারফেক্ট। প্রতিটি টেবিল একে অপরের সাথে `studentId` বা `studentDocId` এর মাধ্যমে সুন্দরভাবে লিঙ্ক করা আছে।

এখন কেবল উপরের **Action Items** গুলো Appwrite-এ সম্পন্ন করলেই আপনার ভর্তি ফর্মটি প্রোডাকশনের জন্য ১০০% রেডি হয়ে যাবে।

আপনার আরও কোনো প্রশ্ন থাকলে বা কোনো অংশ বুঝতে সমস্যা হলে অবশ্যই জানাবেন।
